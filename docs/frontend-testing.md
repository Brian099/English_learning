## 三、测试发现并修复的 Bug

**保存计划会把目标分钟数覆盖成 20。**

`savePlan()` 里写死了 `target_min: 20`，家长在概览页看到的"今日目标"会被悄悄改掉——先设 15 分钟、去计划页点一次保存，就变回 20。

修复：
- 计划页新增「目标」输入框
- 打开时优先回填当天已有计划的目标值，其次用学生的默认目标
- 保存时读取输入框，不再写死

新增断言：改 25 分钟后保存，概览页必须显示 `9/ 25 分钟`。已通过。

## 四、怎么复跑

```bash
# 依赖（只第一次需要）
npm install --prefix .ui-test jsdom@24

# 跑测试
node tools/ui_test.mjs --base http://127.0.0.1:8010 --password dev

# 额外打印各页面渲染文本
node tools/ui_test.mjs --base http://127.0.0.1:8010 --password dev --dump
```

注意：Node 需要 20+；jsdom 30 要 Node 22，所以固定用 `jsdom@24`。

## 五、这个测试没有覆盖的

| 没覆盖 | 说明 |
|---|---|
| **真实视觉渲染** | jsdom 不排版、不计算 CSS，所以布局错位、颜色、响应式都测不出来 |
| **手机窄屏** | 需要真机或 Playwright + 真实浏览器 |
| **视频播放** | 家长端只展示元数据，播放器在孩子端 App，还没做 |
| **多学生切换** | 只有 1 个学生，多卡片的排版未验证 |
| **长时间使用** | 没有压力/并发测试 |

要覆盖视觉和真机，下一步应该上 **Playwright**（能截图 + 真 Chromium），但那需要下载浏览器内核，体积和沙箱限制都要另想办法。

## 七、真机测试暴露的三个问题（2026-10-21 修复）

### 问题 1：点了播放没反应，服务端一条媒体请求都没收到

**现象**：浏览器打开了学生端、配对成功、任务列表正常，但点「开始听」后无声无息。服务端日志里 `/student.html`、`/api/student/today` 都是 200，**却没有任何 `/api/media/...` 请求**。

**根因**：`openPlayer()` 被写成 `async`，函数体里先 `await finalizeSession(...)` 再调 `el.play()`。**`await` 之后浏览器的用户手势授权（transient activation）就失效了**，Chrome 以 `NotAllowedError` 拒绝自动播放，而且因为播放没启动，连媒体请求都不发。

**修复**：
- `openPlayer()` 改为**同步函数**，`el.play()` 放在点击的同步调用栈里
- 上一段的结算改为"先把 session 摘出来、同步开播、再异步上报"
- `finalizeSession(session, item, completed)` 改为显式传参，不再依赖全局状态
- 新增媒体 `error` 事件处理，播放失败时把错误码显示在界面上，不再静默

**回归断言**：`play() 在用户手势内同步调用`——点击后立刻检查 `play()` 的调用次数，必须 > 0。

> 这类 bug jsdom 测不出来（它不实现自动播放策略），只有真浏览器会犯。

### 问题 2：HTML 被 PowerShell 改坏

用 `Get-Content -Raw` + `Set-Content` 批量替换资源版本号时，PowerShell 5.1 默认按 ANSI/GBK 读取 UTF-8 文件，**中文全部变成乱码**（`英语磨耳朵` → `鑻辫纾ㄨ€虫湹`），页面元素 ID 虽然还在但内容已毁。

**教训**：前端文件一律用编辑工具改，不要用 shell 文本命令重写。

**附带修复**：给静态资源加了 `?v=3` 版本号，避免浏览器继续用旧缓存（真机调试时旧 JS 会让人怀疑人生）。

### 问题 3：过期的设备令牌，报错信息完全误导

**现象**：播放报 `播放失败：地址无效或没有权限（4）`。用户自己断开学生端、重新配对后，立刻恢复正常。

**根因**：本地 `localStorage` 里存的设备令牌指向一条已不存在的设备记录（换过数据库、撤销过设备、重新部署都会这样）。媒体地址带着失效令牌请求，浏览器把它归类为 `MEDIA_ERR_SRC_NOT_SUPPORTED`——**这个错误码的字面意思是"格式不支持"，和真实原因（鉴权失败）毫无关系**，所以第一反应会去查文件名和编码。

**修复**：
- 媒体报错且错误码为 4 时，先调 `/api/me` 探测令牌是否有效
- 令牌失效 → 显示「配对已失效，请让家长重新生成配对码」+ 一个「重新配对」按钮，而不是含糊的格式错误
- 令牌有效 → 才提示"地址/格式问题"
- 启动时若 `/api/student/today` 返回 401，也直接回配对页并说明原因

**回归断言**：本地塞一个假令牌 → 打开页面必须自动回到配对页、显示"配对已失效"、并清掉本地令牌。

> **教训**：浏览器的媒体错误码不可信。code 4 既可能是真的格式不支持，也可能是 401/404/令牌失效。区分办法只有一个——单独探测鉴权状态。
