## 三、必须处理的 4 个问题

### 1. 混入中文内容（4/13，占 31%）

`闹闹知识屋` 系列 4 集是**中文睡前故事**（《小满与织梦精灵》《吵吵闹闹又逃学了》等），不是英语启蒙。

**影响**：直接入库会污染统计——孩子"听"了中文内容也算有效时长，家长报表失真。

**对策**：入库时加 `language` 字段，扫描阶段按系列白名单/黑名单过滤，或 ASR 检测语言后自动标记。

### 2. 文件名不可用

实际文件名示例（超过 100 字符）：

```
(小狐狸皮普的英语探险)《甜蜜的陷阱》🐝 糟糕！螳螂要是再空手回家，母螳螂肯定饶不了他！
这次他的计谋能成功吗？胖熊蜂最后又会____fc405366de8dd1a61cddb9b906d74c21.mp4
```

问题：抖音文案 + 话题标签 + emoji + 32 位 hash，人类不可读、URL 编码麻烦、标题无法直接展示。

**对策**：入库时分离"显示标题"与"物理文件"。建议重命名规范：

```
{系列}/{系列}_S{季}E{集}_{中文短标题}.mp4
例：小狐狸皮普的英语探险/小狐狸皮普的英语探险_S01E03_甜蜜的陷阱.mp4
```

标题清洗规则：去掉 `(系列)` 前缀、去掉 `#话题` 标签、去掉 emoji、去掉 `____{hash}` 后缀、截断到 40 字。原始文件名保留在 `original_name` 字段备查。

### 3. 音量跨度 14 dB，存在削波

| 系列 | LUFS | 真峰值 (dBTP) | 评价 |
|---|---|---|---|
| 大嘴狐Omi趣味英语 | −7.6 ~ −8.8 | +1.5 ~ +1.8 | **过响 + 削波** |
| 小狐狸皮普的英语探险 | −9.6 ~ −21.6 | +0.3 ~ +2.9 | **极不一致** |
| 闹闹知识屋 | −17.4 ~ −18.7 | −3.1 ~ −4.0 | 相对正常 |

参考：流媒体平台一般 −14 LUFS，播客 −16 LUFS，广播 −23 LUFS。**−7.6 LUFS 属于异常响度**，真峰值超过 0 dBTP 意味着已经削波失真。

**影响**：孩子在集与集之间要不停调音量，长期大音量听对听力不友好；削波的高频失真对语音清晰度有害。

**对策**：入库流水线加一道 `loudnorm=I=-16:TP=-1.5:LRA=11` 统一响度（一次性处理，转封装不重编码视频）。

### 4. 时长分布与"完成判定"冲突

| 指标 | 值 |
|---|---|
| 最短 / 中位 / 最长 | 20.0 / 80.1 / 219.0 秒 |
| < 30 秒 | **3 集** |
| < 60 秒 | **5 集** |

设计稿 v0.2 里写的规则是「单集连续播放 < 30 秒不产生完成记录」——**会直接误杀这 3 集**（它们总长就不到 30 秒）。

**修正**：完成判定改为相对阈值 + 绝对下限：

```
completed = (max_position_ms / speech_ms >= 0.9) and (effective_ms >= 10_000)
```

即"听完 90% 的**语音**时长，且有效收听 ≥10 秒"，不再用固定 30 秒。

## 四、其他观察

**静音占比极低（0–8%）**
13 集里 12 集的静音（<−30 dB，≥0.6s）占比不到 2%。说明音乐/音效连续铺底，几乎没有真正的静音段。

**影响**：VAD 切不出干净的语音段，Whisper 的幻觉风险比一般素材更高，幻觉过滤（`no_speech_prob` + 压缩比）必须做，不能省。

**1 集是竖屏**（1080×1920，27.8 秒）：播放器需要处理横竖屏切换，磨耳朵模式下无所谓（只听不看），但"看动画"模式要适配。

**主题高度重复**：13 集里有 6 集是"蚂蚁"主题（蚂蚁奇迹、蚂蚁搬家、蚂蚁王国、躲雨…）。这对**间隔复习**是好事——同一主题词汇反复出现，正好符合 i+1 输入原则。

## 五、硬字幕（已确认）

**结论：画面底部有硬字幕，艺术字体，双行双语（中文 + 英文）。**

### 5.1 为什么放弃 OCR

| 条件 | 对 OCR 的影响 |
|---|---|
| 艺术字（描边/渐变/阴影/异形字） | 标准 OCR（Tesseract）基本失效；PaddleOCR 也会大面积错字 |
| 双行双语混排 | 中英混合识别、行切分易错，两行内容还会互相干扰 |
| 逐字高亮/卡拉OK式动画 | 同一句字幕在帧间变化，无法稳定取一帧 |
| 背景是动画画面 | 低对比度、花哨背景，二值化困难 |

即使按最好的情况估，艺术字 OCR 准确率也就在 60–80%，而 Whisper `small.en` 在语音上是 92–95%。**OCR 不仅更差，还要处理逐帧检测、去重、对齐，工程量反而更大。**

→ **转写路线定为 ASR（faster-whisper），OCR 不做。**

### 5.2 但硬字幕带来两个新问题

**问题 A：字幕关不掉，"磨耳朵"会被中文译文破坏。**

双行双语意味着孩子**只要看屏幕就能直接读到中文意思**，完全绕过"听"这个动作。这不是磨耳朵，是看小说。

对策：播放器在"磨耳朵模式"下叠加**底部遮罩**（纯黑不透明条，覆盖底部约 20% 高度），把字幕挡掉。实现上不需要处理视频，一个 overlay View 即可，成本几乎为零。

**问题 B：字幕区域比例不固定。**

横屏 1920×1080 和竖屏 1080×1920 的字幕位置不同。对策：遮罩高度按"屏高的百分比"配置，家长可在播放器里拖动调整一次并存为偏好；或按视频宽高比给两档默认值。

### 5.3 一个意外的好消息

双语字幕说明**内容制作方已经做过本地化**，质量比纯英文的粗糙素材好；而且家长后续校对 ASR 结果时，可以直接对着画面字幕核对——**人工校对成本大幅降低**。

### 5.4 OCR 的唯一残留用途（可选，非必需）

用帧间差分检测"底部哪一条带在频繁变化"，自动判断字幕区域的高度，用于给遮罩设默认值。这是图像处理不是文字识别，实现简单、可靠性高，但属于锦上添花，可以后做。
