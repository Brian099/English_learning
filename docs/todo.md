# 待办与已知限制

记录"暂时不做、以后可能做"的事项，避免反复讨论。

---

## 待决定

### 入库单遍限幅（解决部分素材放不到目标音量）

**现状**：入库只测响度不做归一，播放端按 `gain = 目标响度 − 实测响度` 调音量，
并用真峰值封顶（`gain ≤ −1 − 真峰值`）防止削波。

**问题**：有些素材整体响度低、但真峰值已经顶到 0 dBFS（B 站等平台压过的），
播放端想放大却被峰值卡住，结果达不到目标音量。

实测 21 集里 7 集被卡：

| 集 | 想放大 | 实际只能 | 差距 |
|---|---|---|---|
| id 9 | +5.7 dB | −0.5 dB | 6.2 dB |
| id 20 | +4.7 dB | −0.3 dB | 5.0 dB |
| id 17 | +5.0 dB | +1.5 dB | 3.5 dB |
| id 14 | +1.3 dB | −0.5 dB | 1.8 dB |
| id 16 | +4.3 dB | +2.7 dB | 1.6 dB |
| id 7 | +3.0 dB | +1.9 dB | 1.2 dB |
| id 15 | +8.8 dB | +7.6 dB | 1.2 dB |

**方案 A：播放端加限幅器（Web Audio 压缩器）**

- 能放大又不削波
- 但压缩器必须在 Web Audio 图里 → 每一集都走 Web Audio
- 熄屏播放是核心场景，Web Audio 有挂起风险
- **结论：不做**

**方案 B：入库时对"被峰值卡住"的集做一次单遍限幅**

实测（`alimiter=limit=0.5:level=disabled`）：

```
id   原响度   原峰值   原增益 |  限幅后响度  限幅后峰值  新增益
 9   -21.7   -0.5   -0.5  |   -22.1    -5.4   +4.4
14   -17.3   -0.5   -0.5  |   -17.7    -5.3   +1.7
20   -20.7   -0.7   -0.3  |   -21.1    -5.6   +4.6
```

- 响度只掉约 0.4 dB，峰值降 5 dB，腾出放大空间
- 代价：瞬态（音效、爆破音）会被压平一点，儿童内容基本听不出
- 做法：测量后判断 `目标−实测 > (−1−真峰值) + 2dB` 才重编，只影响少数集
- **结论：暂不做，等实际使用后再决定**

## 已知限制

- **浏览器端放大依赖 Web Audio**：衰减（负增益）用 `element.volume` 即可，
  放大必须走 Web Audio 增益节点；环境不支持时只能保持原音量。
- **内容库是全局共享的**：多个家庭共用同一批视频，只有一个媒体目录。
- **中文素材不会自动过滤**：扫描不区分语言，中文视频也会入库并参与排片。
- **没有 SRT 导出**：对白只存数据库，不生成字幕文件。
