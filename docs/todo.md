## 待决定

### 入库单遍限幅（解决部分素材放不到目标音量）

**现状**：入库只测响度不做归一，播放端按 `gain = 目标响度 − 实测响度` 调音量，
并用真峰值封顶（`gain ≤ −1 − 真峰值`）防止削波。

**问题**：有些素材整体响度低、但真峰值已经顶到 0 dBFS（B 站等平台压过的），
播放端想放大却被峰值卡住，结果达不到目标音量。

实测 21 集里 7 集被卡：

| 集 | 想放大 | 实际只能 | 差距 |
|---|---|---|---|
| id 9 | +5.7 dB | −0.5 dB | 6.2 dB |
| id 20 | +4.7 dB | −0.3 dB | 5.0 dB |
| id 17 | +5.0 dB | +1.5 dB | 3.5 dB |
| id 14 | +1.3 dB | −0.5 dB | 1.8 dB |
| id 16 | +4.3 dB | +2.7 dB | 1.6 dB |
| id 7 | +3.0 dB | +1.9 dB | 1.2 dB |
| id 15 | +8.8 dB | +7.6 dB | 1.2 dB |

**方案 A：播放端加限幅器（Web Audio 压缩器）**

- 能放大又不削波
- 但压缩器必须在 Web Audio 图里 → 每一集都走 Web Audio
- 熄屏播放是核心场景，Web Audio 有挂起风险
- **结论：不做**

**方案 B：入库时对"被峰值卡住"的集做一次单遍限幅**

实测（`alimiter=limit=0.5:level=disabled`）：

```
id   原响度   原峰值   原增益 |  限幅后响度  限幅后峰值  新增益
 9   -21.7   -0.5   -0.5  |   -22.1    -5.4   +4.4
14   -17.3   -0.5   -0.5  |   -17.7    -5.3   +1.7
20   -20.7   -0.7   -0.3  |   -21.1    -5.6   +4.6
```

- 响度只掉约 0.4 dB，峰值降 5 dB，腾出放大空间
- 代价：瞬态（音效、爆破音）会被压平一点，儿童内容基本听不出
- 做法：测量后判断 `目标−实测 > (−1−真峰值) + 2dB` 才重编，只影响少数集
- **结论：暂不做，等实际使用后再决定**

## 待决定

### 视频放云盘（OpenList / WebDAV）

**背景**：同一批视频在云盘也存一份，通过 OpenList 挂载，想让播放走云盘、省 NAS 空间。
规模参考：1923 个文件，23.9 GB。

**方案对比**

| 方案 | 改动 | 问题 |
|---|---|---|
| OpenList 直链（302 跳转） | 要改接口+前端 | 跨域导致 Web Audio 静音（音量放大、人声增强全废）；直链可能过期；依赖云盘 Range |
| **WebDAV 挂到宿主机 → 映射进容器** | **零改动** | 需要网络挂载的稳定性保障 |
| 容器内挂载 | 要改镜像 + SYS_ADMIN 提权 | 挂载随容器死，排错困难 |

**结论：用 WebDAV 宿主机挂载**，容器只读绑定。

**rclone 缓存模式的坑（重要）**

- `--vfs-cache-mode full`：文件一被打开就后台下载整集
  → 扫描时对每集跑 ffprobe，等于把 23.9 GB 全下了一遍
- 应该用 `off` + 调大 chunk，扫描只读文件头（总共几十 MB）：

```bash
rclone mount openlist:/ /vol1/1000/media/cloud \
  --vfs-cache-mode off \
  --vfs-read-chunk-size 8M \
  --vfs-read-chunk-size-limit 64M \
  --allow-other --read-only --daemon
```

**成本估算（1923 集 / 23.9 GB）**

| 步骤 | 耗时 |
|---|---|
| 下载（@50Mbps） | ~1 小时 |
| 抽音轨 | ~2 小时 |
| 测响度 | ~1 小时 |
| **转写（N100 / small.en）** | **~40 小时** |

入库必然要读完整文件（抽音轨+测响度+转写），这部分绕不开。
真正的瓶颈是转写，不是带宽。

**配套要做的两件事**

1. **快速入库开关**：跳过转写，只抽音轨+测响度（1923 集约 3 小时）。
   代价是没有难度分级和语音占比，但排片、播放、时长统计、音量统一都正常。
2. **缺失比例保护**：网络挂载掉线时，扫描会把"库里有、磁盘上没有"的记录
   彻底删除（连带学生计划、播放记录）。现有安全阀只覆盖"一个文件都没扫到"，
   需要加一条：缺失比例超过阈值（如 30%）时拒绝清理，只报告。

**结论：先不做，等需要扩容时再实施。**

## 已知限制

- **浏览器端放大依赖 Web Audio**：衰减（负增益）用 `element.volume` 即可，
  放大必须走 Web Audio 增益节点；环境不支持时只能保持原音量。
- **内容库是全局共享的**：多个家庭共用同一批视频，只有一个媒体目录。
- **中文素材不会自动过滤**：扫描不区分语言，中文视频也会入库并参与排片。
- **没有 SRT 导出**：对白只存数据库，不生成字幕文件。
